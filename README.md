# 위의 군략

리마스터 도트 전장과 정교한 인물 초상을 사용하는 삼국지 턴제 전술 RPG.

현재 **영천·사수관·호로관 3개 전투를 플레이할 수 있는 웹 버전**이다. 전투 선택 → 군의 대화와 선택 → 출진 준비 → 전투 → 결과 → 다음 전투를 연결했다. 모든 전투를 바로 선택해 시작하거나 영천부터 순서대로 진행할 수 있다. 데스크톱은 승인한 콘셉트의 메뉴 구성을 유지하고, 모바일 세로에서는 준비 정보를 스크롤하며 보고 전투 정보를 지도 아래에 표시한다.

## 공개 플레이와 배포

[GitHub Pages에서 게임 실행](https://gnsyoo.github.io/threekingdom-jojo/)

`main`에 푸시하면 GitHub Actions가 의존성 설치, 전술 규칙 테스트, 타입 검사와 빌드를 수행하고 `dist/`를 Pages에 배포한다. 저장소 Pages의 배포 소스는 GitHub Actions다. Actions 화면에서 `Deploy game to GitHub Pages`를 수동 실행할 수도 있다.

최초 배포는 [Settings → Pages](https://github.com/gnsyoo/threekingdom-jojo/settings/pages)에서 **Build and deployment → Source → GitHub Actions**를 선택해 사이트를 활성화한 뒤 진행한다. 이후 `main` 푸시 또는 워크플로의 `Run workflow`로 배포한다. 이 초기 설정에는 저장소의 Pages 설정 권한이 필요하다. 연동 토큰으로 활성화할 경우 GitHub App의 `administration:write`와 `pages:write` 권한이 모두 필요하다.

```bash
npm run build:pages
npm run preview -- --port 4173 --strictPort
```

Pages 빌드는 `/threekingdom-jojo/` 경로를 사용한다. 전장·초상·부대·폰트와 동적으로 로드하는 전투 엔진도 이 경로에서 제공한다. 브라우저 저장 기록은 실행한 사이트의 주소별로 관리되므로 로컬 기록을 공개 사이트로 옮기려면 저장 파일 내보내기·불러오기를 사용한다.

## 실행

Node.js 24를 사용한다.

```bash
cd /workspace/threekingdom-jojo
npm ci --cache /workspace/.cache/npm --no-audit --no-fund
npm run dev -- --port 5173 --strictPort
```

개발 서버는 포트 5173에서 모든 인터페이스에 바인딩한다. 호스팅 환경이 제공하는 포트 접근 기능을 통해 연다. 비밀 키·로그인·외부 API·데이터베이스는 필요하지 않다.

```bash
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium을 사용한다. 다른 위치라면 `CHROMIUM_PATH`에 실행 파일 경로를 지정한다. 설치되지 않은 머신에서는 Chromium을 별도로 준비해야 한다. 브라우저를 자동 다운로드하지 않는다.

프로덕션 결과는 `dist/`다. `npm run preview -- --port 4173 --strictPort`로 빌드 결과를 내부에서 검증할 수 있다.

## 구현된 전투

| 전투 | 지도 | 목표·이벤트 | 제한 |
|---|---|---|---|
| 영천 | 18×12 | 장보·장량 퇴각, 2턴 화공, 민가 확인 | 12턴 |
| 사수관 구원전 | 22×14 | 화웅 퇴각, 부상한 손견 구원, 3턴 관우 지원 | 16턴 |
| 호로관 | 24×14 | 여포 퇴각, 3턴부터 여포 진격, 우군 2명 생존 | 18턴 |

사수관은 북쪽 관문과 서쪽 숲길, 호로관은 동쪽 성문과 넓은 평지로 구성했다. 두 전투의 전장, 손견·화웅·여포 초상, 보스의 걷기·공격 스프라이트를 새로 제작했다.

## 가능한 것

- 양쪽 인물 초상과 군의 배경, 대화 기록, 선택 전까지 자동 재생.
- 출진 무장 목록, 선택 장수 초상·레벨·HP/MP·기본 장비 정보, 출진 위치 미리보기.
- 출진 지원금 200냥으로 회복약 구매·되팔기, 조조 시작 위치 변경과 확정.
- 조조 직접 조작, 유비·관우·장비와 손견의 우군 AI, 황건군·동탁군의 적 AI. 사수관의 관우는 3턴에 합류한다.
- 18×12·22×14·24×14 전장, 가중 이동 비용, 물·건물 통행 차단, 숲·진영 방어, 다리, 민가 회복.
- 이동 경로 미리보기·확정·이동 되돌리기, 공격·명중·반격 예측과 판정.
- 자신 또는 인접한 우군에게 회복약 사용, 격려 책략, 대기, 아군→우군→적군의 라운드 진행.
- 영천의 2라운드 화공·일반병 혼란. 전투별 지휘관 퇴각 승리, 조조 퇴각·턴 제한 초과 패배.
- 전투별 보조 목표, 전장 기록, 승패 결과와 다음 전투. 제목의 전투 선택에서 재도전과 승리 기록 확인.
- 호로관의 지휘관 위협 범위 표시, 지도 드래그·확대·전체 보기, 모바일 세로 중심 배치와 가로 대응, 터치·키보드 명령, 효과음과 속도 설정.
- 배경 명도를 낮춘 전장, 장수 윤곽과 진영별 바닥·깃발·이름표, 색상과 모양을 함께 쓰는 진영 표시.
- 경로를 따라 걷기, 공격 자세, 궁병의 화살, 피격·회피·반격·퇴각 연출. 다음 AI 행동과 결과 화면은 동작 재생을 기다린다.
- 자동 저장, AI 차례 중 복귀, 이전 정상 백업 복구, 파일 내보내기·가져오기.

## 조작

1. `영천으로 출진` 또는 `전투 선택`에서 전투를 고른다. 군의 대화를 읽고 보급 또는 선봉 강화를 선택한 뒤 `출진 준비로`를 누른다.
2. 장수와 기본 장비를 확인하고, `배치`에서 조조의 시작 위치를 확정한다. `상점`에서 회복약을 준비한 뒤 `출진`한다.
3. 파란 칸을 누르고 경로를 확인한 뒤 `확정`으로 이동한다.
4. `공격`을 선택하고 인접한 적을 누른다. 피해·명중·명중 시 반격을 확인한 뒤 확정한다.
5. 조조의 행동이 끝나면 `턴 종료`로 우군과 적군의 행동을 진행한다.
6. 해당 전투의 지휘관을 퇴각시키면 승리한다. 결과 화면에서 다음 전투로 진군하거나 전투 선택으로 돌아간다. 체력이 낮으면 `도구`에서 회복 대상을 고르고 확정한다.

키보드: `1` 이동, `2` 공격, `3` 책략, `4` 도구, `5` 대기, `Space` 턴 종료, `Esc` 취소·메뉴. 지도는 드래그·휠·두 손가락으로 이동·확대할 수 있다.

## 저장

진행 중이거나 끝난 마지막 전투는 브라우저 `localStorage`에 저장한다. 이동 미확정 상태, 부대 행동 여부, 라운드·진영, 전투 ID·지도·이벤트 실행 기록·난수 상태를 함께 보관한다. 같은 상태의 중복 저장은 백업을 갱신하지 않는다. 브라우저 데이터를 삭제하면 기록이 사라질 수 있으므로 메뉴에서 파일로 내보낼 수 있다.

준비 화면의 구매와 배치는 메뉴를 오가도 유지된다. `출진`할 때 전투 기록에 반영한다. 출진 전 새로고침하면 준비 중인 변경은 초기화되며, 이전 전투 기록은 출진할 때까지 보관한다.

저장 버전 1의 스키마·좌표·능력치·점유·판정 일관성을 각 전투의 명세와 비교한 뒤 불러온다. 이전 영천 기록은 전투 ID와 이벤트 필드를 보완해 그대로 이어갈 수 있다. 전투별 승리 표시는 별도 로컬 캠페인 기록으로 저장하며, 내보내기 파일에는 마지막 전투가 들어간다. 유효하지 않은 기록은 적용하지 않는다. 캠페인 규모가 커지면 저장 인터페이스를 유지하면서 IndexedDB로 확장할 계획이다.

## 구조

- `src/scenarios.ts`: 3개 전투의 지도·목표·대화·명단·배치·턴 제한.
- `src/core.ts`: DOM·렌더러와 분리한 전술 규칙, AI, 시나리오 상태, 저장 검증.
- `src/battle-scene.ts`: Phaser 지도, 경로 이동·걷기·공격·피격 애니메이션, 카메라와 터치.
- `src/main.ts`: 제목·대화·준비·명령·목표·설정·결과 UI와 전투 진행.
- `src/preparation.ts`: 출진 무장·장비 정보·보급 구매·시작 위치 설정.
- `src/art.ts`, `src/concept.css`: 초상·아이콘과 데스크톱 콘셉트 배치.
- `src/mobile.css`: 대화창 재질, 버튼 글자, 세로 준비·전투 배치와 화면 크기 대응.
- `src/storage.ts`: 자동 저장·백업·내보내기와 전투별 승리 기록.
- `public/assets/`: 새로 생성한 군의실·야영지·전장·초상·장비·부대 동작, 자체 호스팅 폰트.
- `tests/core.test.ts`: 이동·행동·AI·승패·저장과 완주 검증.
- `tests/browser/`: 실제 브라우저에서 화면·조작·복귀·완주 검증.

전투 엔진은 출진 시 동적으로 불러온다. 제목 화면의 JavaScript는 약 65KB, 엔진 청크는 약 1.49MB(압축 시 약 345KB)다. Phaser 청크 크기 경고는 남아 있으며 다음 최적화 단계에서 엔진 구성·정적 리소스 용량을 검토한다.

## 현재 범위

웹에서 3개 전투를 구현했다. 현재 10종 부대에 걷기 4포즈·공격 4포즈씩 총 80개 동작 프레임을 사용하고, 좌우 이동·공격에는 반전을 적용한다. 독립된 4방향 프레임은 다음 아트 제작 범위다.

장비 메뉴는 지급된 기본 장비 정보 확인까지 구현했다. 조조의 Lv.3·4·5와 각 전투의 능력치는 시나리오 시작값이다. 경험치 표시는 초기값이며 전투 뒤 경험치 지급·장비 교체·강화·승급·전리품 정산은 아직 구현하지 않았다. 호로관 이후 캠페인과 Android/iOS 네이티브 패키징도 후속 제작 범위다.

모바일 화면은 Chromium의 320·390·412px 세로 터치, 768px 태블릿과 가로·화면 회전 환경으로 검증한다. 실제 기기 성능, 앱 설치·서명·스토어 배포는 별도의 검증 단계다. 브라우저 최초 실행에는 정적 파일 다운로드가 필요하고, 다운로드 완료 후 전투 판정은 외부 서버에 의존하지 않는다.
