# 사마의전 · 중달의 군략

사마의의 시점으로 상용·오장원·요동을 지휘하는 모바일 중심 삼국지 전술 RPG다. 현재 구현된 **세 전투와 전투 전후 이야기 전체를 사마의전으로 교체**했다. 군의·전략 선택 → 출진 준비 → 전투 → 사마의의 독백 → 다음 원정으로 진행한다.

[공개 게임 실행](https://gnsyoo.github.io/threekingdom-jojo/) · [시나리오와 실제 화면](docs/prototype/SIMA_CAMPAIGN.md)

## 공개 플레이와 배포

[GitHub Pages에서 게임 실행](https://gnsyoo.github.io/threekingdom-jojo/)

`main`에 푸시하면 GitHub Actions가 의존성 설치, 전술 규칙 테스트, 타입 검사와 빌드를 수행하고 `dist/`를 Pages에 배포한다. 저장소 Pages의 배포 소스는 GitHub Actions다. Actions 화면에서 `Deploy game to GitHub Pages`를 수동 실행할 수도 있다.

최초 배포는 [Settings → Pages](https://github.com/gnsyoo/threekingdom-jojo/settings/pages)에서 **Build and deployment → Source → GitHub Actions**를 선택해 사이트를 활성화한 뒤 진행한다. 이후 `main` 푸시 또는 워크플로의 `Run workflow`로 배포한다. 이 초기 설정에는 저장소의 Pages 설정 권한이 필요하다. 연동 토큰으로 활성화할 경우 GitHub App의 `administration:write`와 `pages:write` 권한이 모두 필요하다.

```bash
npm run build:pages
npm run preview -- --port 4173 --strictPort
```

Pages 빌드는 `/threekingdom-jojo/` 경로를 사용한다. 전장·초상·부대·폰트와 동적으로 로드하는 전투 엔진도 이 경로에서 제공한다. 브라우저 저장 기록은 실행한 사이트의 주소별로 관리되므로 로컬 기록을 공개 사이트로 옮기려면 저장 파일 내보내기·불러오기를 사용한다.

## 실행

Node.js 24를 사용한다.

```bash
cd /workspace/threekingdom-jojo
npm ci --cache /workspace/.cache/npm --no-audit --no-fund
npm run dev -- --port 5173 --strictPort
```

개발 서버는 포트 5173에서 모든 인터페이스에 바인딩한다. 호스팅 환경이 제공하는 포트 접근 기능을 통해 연다. 비밀 키·로그인·외부 API·데이터베이스는 필요하지 않다.

```bash
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 시스템 Chromium을 사용한다. 다른 위치라면 `CHROMIUM_PATH`에 실행 파일 경로를 지정한다. 설치되지 않은 머신에서는 Chromium을 별도로 준비해야 한다. 브라우저를 자동 다운로드하지 않는다.

프로덕션 결과는 `dist/`다. `npm run preview -- --port 4173 --strictPort`로 빌드 결과를 내부에서 검증할 수 있다.

## 구현된 원정

| 연도·전투 | 지도 | 승리 조건 | 사건·보조 목표 |
|---|---|---|---|
| 228년 상용 급습전 | 18×12 | 12턴 안에 맹달 제압 | 2턴 연락로 차단·일반병 혼란, 민가 확인 |
| 234년 오장원 대치전 | 22×14 | 사마의가 생존한 채 8턴 시작 | 3턴 곽회 합류, 부상한 우금 구원 |
| 238년 요동 포위전 | 24×14 | 18턴 안에 공손연·비연 제압 | 3턴 양평 반격, 우군 2명 이상 생존 |

오장원은 적 지휘관을 처치할 필요가 없는 방어전이다. 목표·진행 표시·승패·저장 검증에도 이 규칙을 적용한다. 각 원정의 도입 대화 여섯 장면, 전략 선택, 승리 후 대화 두 장면과 사마의의 독백을 작성했다. 역사적 사건을 바탕으로 전장 배치·부대 편성·대사를 각색했다. 우금은 위나라 장수 **牛金(Niu Jin)**이다.

## 화면과 조작

- 제목·군의·명령·준비·결과의 주인공은 사마의다. 사마사·우금·곽회·호준이 우군으로 등장한다.
- 사마의·사마사·우금·곽회·호준·맹달·제갈량·공손연의 새 초상과 64개 걷기·공격 프레임, 새 전장 세 장을 사용한다. 일반 보병·궁병 동작 16프레임을 더해 총 80프레임이다.
- 선택 장수의 **몸과 무기를 포함한 가로·세로 크기를 44 전장 픽셀 안에 맞추고**, 발 위치를 칸 바닥에서 14픽셀 위에 둔다. 깃발·체력바·공격 전진도 칸의 여백을 고려한다.
- 브라우저 글자로 표시한 12px 이름·지명, 최대 2배 캔버스 해상도와 부드러운 이미지 필터를 유지한다. 진한 발밑 그림자는 없다.
- 세로 화면에서는 준비 본문을 스크롤하고 하단 메뉴를 고정한다. 전투 정보는 지도 아래에, 가로에서는 오른쪽에 표시한다.
- 기본 장비 확인, 사마의 시작 위치 선택, 200냥 지원금으로 회복약 구매·되팔기·최대 3개 보급을 제공한다.
- 이동 미리보기·확정·되돌리기, 공격·명중·반격 예측, 자신 또는 인접한 우군 회복, 격려·대기·턴 종료를 제공한다.

1. `상용으로 출진` 또는 `전투 선택`으로 원정을 고른다.
2. 군의를 읽고 전략을 선택한 뒤 장수·장비·보급·배치를 확인한다.
3. 파란 칸을 탭해 이동을 확정하고 공격·책략·도구·대기 중 한 행동을 한다.
4. 턴을 종료하면 우군과 적군이 차례로 행동한다. 지도는 드래그·확대·전체 보기로 살핀다.
5. 각 전투의 목표를 달성하면 승리 후 이야기를 읽고 다음 원정으로 진행한다.

키보드: `1` 이동, `2` 공격, `3` 책략, `4` 도구, `5` 대기, `Space` 턴 종료, `Esc` 취소·메뉴.

## 저장과 구조

사마의전은 `simayi-chronicle.battle.v2`·백업·캠페인 저장을 사용한다. 기존 조조편의 `wei-tactics.*.v1` 기록은 덮어쓰거나 지우지 않는다. 두 캠페인의 서로 다른 지도·명단을 섞어 불러오지 않는다. 사마의전은 자동 저장, AI 행동 중 복귀, 정상 백업, JSON 내보내기·가져오기를 지원한다.

- `src/scenarios.ts`: 세 원정의 대화·명단·지도·목표·선택·후일담.
- `src/core.ts`: 전술 규칙, 급습·지원·반격, 제압/방어 승패, 저장 검증.
- `src/battle-scene.ts`: 고해상도 전장·동작, 칸 안의 캐릭터 배치와 고정 크기 이름표.
- `src/main.ts`, `src/preparation.ts`: 제목·군의·준비·명령·목표·결과 흐름.
- `src/art.ts`, `src/polish.css`: 비율을 보존하는 초상·장비·부대 아틀라스와 화면 배치.
- `public/assets/sima-*`, `*-map.png`: 새 사마의전 리소스. 원본 PNG를 수정하지 않고 프레임 영역으로 표시한다.
- `tests/core.test.ts`, `tests/browser/`: 전술 규칙·합법적인 전투 완주·실제 화면과 터치·회전·저장 검수.
