# 50개 전투 확장 · UI·스토리 23회와 품질 50회 검수

아홉 주요 원정을 **50개의 플레이 가능한 전술 전투**로 연결했다. 거점 확보 19개, 방어 12개, 회군·호위 10개, 격파 9개다. 전체 대사와 게임/원전의 경계는 [SIMA_CAMPAIGN.md](SIMA_CAMPAIGN.md)에 기록한다.

## 검증 방법

아래 번호는 서로 다른 실제 브라우저 사례다. 동일한 단순 검사를 50번 반복하거나 50회 수동 완주했다고 주장하지 않는다. Chromium에서 작은 폰·세로 폰·가로 폰·태블릿·데스크톱 화면을 검사하고 자동 캡처를 별도로 눈으로 검토했다. UI·스토리 23개 사례와 품질 50개 사례를 구별한다. 지도 검사는 별도로 50전투×세로 폰/데스크톱 100개 사례다. 실물 Android/iOS 기기 QA는 별도다.

- UI·스토리: 군의의 각 대사, 중간 장면 저장·복귀, 원정 분류, 전략 선택·준비 진행 표시, 후일담, 다음 전투의 첫 대사와 여정 ID를 실제 UI로 확인한다. 승리 상태는 규칙 API로 합법적으로 완료한 fixture이며 이 23개 사례를 직접 UI 전투 완주 23회로 세지 않는다.
- 품질: 버튼 텍스트가 버튼 경계를 벗어나는지, 페이지 가로 넘침·좌우 밀림, 초상·장비의 비율, 44px 행동 버튼, 자원 로딩 오류·예외, 회전·우군 방침 등을 검사한다. 완료 목록 fixture는 최대 메뉴·금액·종막 접근 상태를 재현하기 위한 것이다.
- 전투 규칙: 50전투×두 전략×세 난수 시드 **300회 합법적 완료**, 행동과 AI 진행마다 저장 재검증. 전체 연결 검사에서 50회를 추가 완료한다.
- 지도: 각 전투의 파일 디코딩·실제 HTTP 바이트·해상도, 준비 지도 비율, 배치창의 실제 3×3 구역, 전투 표시·전체 지도 양쪽 끝·회전을 확인한다. 50개 파일의 SHA-256은 모두 다르다.

## 최종 실행 결과

- `npm test`: **149개 통과**. 300회 전략/난수 조합 완료와 전체 50전투 연결 완료를 포함한다.
- 브라우저 **220개 고유 사례 통과**: 지도 100개, UI·스토리 23개, 품질 50개, 검색·서막·지휘관 이름 3개, 기존 전투·저장·회전·스와이프 44개.
- 지도 최초 100개 검수 후 보정한 가정·양평 두 지도를 세로/데스크톱으로 **4개 재검수**했고 모두 통과했다.
- 첫 UI·스토리 검수의 320px 버튼 겹침·가로 넘침 실패는 수정 후 23개 전체를 다시 실행해 통과했다. 기존 오장원 연결 검수의 고정 대화 횟수/전투 ID 가정도 새 요동 진군로에 맞춰 갱신하고 해당 캠페인 검사 5개를 재실행해 모두 통과했다. 중단·실패했던 최초 실행을 통과 횟수에 합산하지 않는다.
- `npm run build:pages`: 타입 검사·Pages 경로 빌드 통과.
- GitHub Pages [배포 실행 37187137438](https://github.com/gnsyoo/threekingdom-jojo/actions/runs/37187137438): 구현 커밋 `916c6bee`의 CI 규칙 검사·빌드·배포 모두 성공.
- [공개 게임](https://gnsyoo.github.io/threekingdom-jojo/)의 지도 50장·아트/메타데이터 5개·폰트 8종·JS/CSS 3개, 총 **66개 파일**의 SHA-256이 로컬 Pages 빌드와 일치했다. HTTPS 인증서·호스트 검증을 유지했다.
- 공개본 **50개 전투 전부**에서 전략 선택→준비→출진→2라운드→새로고침·이어하기를 검사했다. 장수 위치·HP·사건 기록 복구, 세로→가로→세로 회전, 지도 로딩·런타임 오류·가로 넘침 검사가 모두 통과했다. 양평관 다섯 전투의 지휘관은 사마사다. Chromium에 세션 프록시로 받은 실제 공개 HTTPS 응답을 전달하며 개발 서버나 로컬 빌드 파일로 대체하지 않았다.
